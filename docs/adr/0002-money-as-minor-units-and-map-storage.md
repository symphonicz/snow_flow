# เก็บจำนวนเงินเป็นหน่วยย่อย ×100 ทุกสกุล และเก็บรายการลง hive_ce เป็น Map

ในเครื่อง SnowFlow เก็บจำนวนเงินเป็นจำนวนเต็มหน่วยย่อยที่**คูณ 100 เสมอทุกสกุลเงิน** เช่น 60.50 บาท เก็บเป็น `6050` และ 500 เยน เก็บเป็น `50000` แม้เยนจะไม่มีทศนิยม เหตุผลคือ ทศนิยมแบบ double บวกกันแล้วเพี้ยนได้ (0.1 + 0.2 ≠ 0.3) ส่วนการใช้ตัวคูณตามสกุล (บาท ×100, เยน ×1) ต้องมีตารางที่ห้ามเปลี่ยนตลอดไป ถ้าวันหน้ากฎทศนิยมของสกุลไหนเปลี่ยน ข้อมูลเก่าจะถูกแปลผิด เรื่องที่ว่า "เยนไม่มีทศนิยม" จึงจัดการแค่ตอนแสดงผลและตอนกรอกในฟอร์ม ส่วนไฟล์สำรองยังเขียน `amount` เป็นทศนิยมเหมือนเดิม

แต่ละรายการเก็บลง hive_ce เป็น **Map** ที่ใช้ชื่อฟิลด์ชุดเดียวกับไฟล์สำรอง (ต่างกันแค่ `amount` ที่เป็นหน่วยย่อย) แปลงไปกลับด้วย `toMap()` / `fromMap()` ที่เขียนเอง ไม่ใช้ TypeAdapter เพราะ adapter ผูกกับ type id และหมายเลขฟิลด์ที่ห้ามเปลี่ยนตลอดไป แถมต้องรันคำสั่งสร้างโค้ด ส่วน Map เพิ่มฟิลด์ใหม่ได้โดยให้ `fromMap` ใส่ค่าเริ่มต้นแทนการย้ายข้อมูลทั้งก้อน รายละเอียดอยู่ที่ [ตัดสินใจ: รูปแบบเก็บข้อมูลภายใน (เงิน วันที่ id คลาส)](https://github.com/symphonicz/snow_flow/issues/17)

## Considered Options

- **เงินเป็น double**: ไม่เลือก เพราะยอดรวมหลายรายการเพี้ยนได้
- **เงินเป็นหน่วยย่อยตามสกุล** (เยน ×1): ไม่เลือก เพราะต้องมีตารางตัวคูณที่ห้ามเปลี่ยน และถ้าแก้ตารางผิดครั้งเดียว ข้อมูลเก่าจะแปลผิดทั้งหมด
- **package `decimal`**: ไม่เลือก เพราะแม่นยำเท่ากันแต่ใช้ยากกว่าและต้องเพิ่ม package
- **TypeAdapter ที่สร้างอัตโนมัติ (`hive_ce_generator`) หรือเขียน adapter เอง**: ไม่เลือก ด้วยเหตุผลข้างบน

## Consequences

- ห้ามเปลี่ยนความหมายของ `amount` ในกล่องข้อมูล (หน่วยย่อย ×100) ถ้าเปลี่ยนต้องเขียนโค้ดย้ายข้อมูลเก่า
- การแปลงระหว่างหน่วยย่อยกับทศนิยมในไฟล์สำรองต้องอยู่จุดเดียว และต้องมี unit test
- ชื่อ key ใน Map ต้องคงที่ เช่นเดียวกับชื่อกล่องใน [ADR 0001](0001-hive-ce-for-local-storage.md)
- ถ้า Map ที่อ่านขึ้นมามีฟิลด์ขาดหรือชนิดผิด ให้แสดงหน้าจอแจ้งปัญหาตามข้อสรุปของ #16 ไม่ลบข้อมูลเอง
