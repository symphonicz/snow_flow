# ใช้ hive_ce เก็บข้อมูลในเครื่อง ไม่ใช้ drift

SnowFlow เก็บรายการและการตั้งค่าไว้ในเครื่องด้วย hive_ce (บนเว็บใช้ IndexedDB) เพราะข้อมูลมีขนาดเล็กและค้นไม่ซับซ้อน การกรองตามรอบเดือนจึงเขียนในโค้ดเองได้ ส่วน drift ที่เป็น SQLite มีข้อเสียบนเว็บซึ่งโฮสต์บน GitHub Pages หลายข้อ ได้แก่ ต้องวาง `sqlite3.wasm` และ `drift_worker.js` เพิ่ม ตั้ง header COOP/COEP ไม่ได้ ถ้าไม่มีที่เก็บข้อมูลที่ใช้ได้จะเก็บไว้ในหน่วยความจำโดยไม่แจ้ง (ปิดแอปแล้วข้อมูลหาย) และเวอร์ชันใหม่ต้องใช้ Dart 3.10 ซึ่งต้องอัปเกรด Flutter ก่อน รายละเอียดอยู่ที่ [ตัดสินใจ: วิธีเก็บข้อมูลในเครื่อง](https://github.com/symphonicz/snow_flow/issues/16)

## Considered Options

- **drift** (SQLite): ไม่เลือก ด้วยเหตุผลข้างบน ถ้าอนาคตข้อมูลโตจนการโหลดทุกรายการขึ้นหน่วยความจำช้าเกินไป ค่อยกลับมาพิจารณา
- **sembast**: เวอร์ชันใหม่ต้องใช้ Dart 3.10 เหมือน drift
- **shared_preferences**: เอกสารของ package เองบอกว่าห้ามใช้เก็บข้อมูลสำคัญ และบนเว็บเก็บได้แค่ 5 MiB
- **isar / objectbox / sqflite**: isar หยุดพัฒนาไปแล้ว objectbox ไม่มีเวอร์ชันเว็บ sqflite บนเว็บยังเป็นรุ่นทดลอง

## Consequences

- ชื่อ key และ type id ของ hive_ce ต้องคงที่ตลอดไป ห้ามใช้ชื่อคลาส เพราะชื่อคลาสเปลี่ยนตอน build เว็บแบบ release
- ชื่อกล่องข้อมูลต้องมี prefix เฉพาะแอป เพราะทุก repo ใต้ `symphonicz.github.io` ใช้ที่เก็บข้อมูลของเบราว์เซอร์ร่วมกัน
- ถ้าเปลี่ยนรูปแบบข้อมูล ต้องเขียนโค้ดย้ายข้อมูลเก่าเอง เพราะ hive_ce ไม่มีระบบ migration
