# SnowFlow — Project Brief สำหรับพัฒนาด้วย Flutter

เอกสารนี้รวมทุกอย่างที่ตัดสินใจแล้วระหว่างออกแบบ ใช้เป็นแหล่งอ้างอิงหลักตอนพัฒนา

**สำคัญ:** เรื่องที่เขียนว่า "ตัดสินแล้ว" ให้ทำตาม ส่วนเรื่องทางเทคนิคที่อยู่ในหัวข้อ "ยังไม่ได้ตัดสินใจ" ให้แนะนำตัวเลือกพร้อมข้อดีข้อเสีย แล้วถามเจ้าของโปรเจกต์ก่อนเลือกเสมอ ถ้ามีจุดที่ขัดกันหรือไม่ชัด ให้ถามก่อนเดา

---

## 1. ภาพรวม

SnowFlow คือแอปจดรายรับรายจ่ายประจำวันแบบง่ายสำหรับคนทั่วไป เป้าหมายหลักคือให้ผู้ใช้ **รู้ว่าเงินหมดไปกับอะไรบ้าง**

- เปิดแล้วใช้ได้ทันที ไม่ต้องสมัครสมาชิก ไม่มีเซิร์ฟเวอร์
- ข้อมูลเก็บในอุปกรณ์แต่ละเครื่องเท่านั้น ย้ายข้อมูลข้ามเครื่องด้วยไฟล์สำรอง .json
- แพลตฟอร์ม: เว็บ, iOS, Android จากโค้ดชุดเดียว
- ภาษา: ไทย (หลัก) และอังกฤษ
- ธีม: สว่าง / มืด / ตามระบบ (ค่าเริ่มต้น)

## 2. เทคโนโลยี

### ตัดสินแล้ว
- **Flutter** + Dart โค้ดชุดเดียวสำหรับ web, iOS, Android
- ทำงานออฟไลน์ได้ทั้งหมด ไม่มีเซิร์ฟเวอร์ ไม่มีบัญชีผู้ใช้ ข้อมูลอยู่ในเครื่องเท่านั้น
- ฟอนต์ Prompt ต้องอยู่ในโปรเจกต์ (ห้ามโหลดจากเน็ตตอนรัน)
- ค่าดีไซน์ทั้งหมดรวมอยู่ในไฟล์ธีมไฟล์เดียว ตามข้อ 6
- ต้องมี unit test สำหรับ logic รอบเดือน ยอดคงเหลือ การจัดกลุ่มสรุป และการนำเข้า/ส่งออก

### ยังไม่ได้ตัดสินใจ — ให้แนะนำตัวเลือกพร้อมข้อดีข้อเสีย แล้วถามเจ้าของโปรเจกต์ก่อนเลือก
- โครงสร้างโฟลเดอร์และสถาปัตยกรรมของแอป
- state management
- วิธีเก็บข้อมูลในเครื่อง (ต้องรองรับเว็บด้วย)
- วิธีทำกราฟแท่งแบบซ้อนสี (ใช้ package หรือวาดเอง)
- วิธีแปลภาษาไทย/อังกฤษ
- วิธีส่งออก/นำเข้าไฟล์ในแต่ละแพลตฟอร์ม
- วิธีทำแจ้งเตือนรายวันบนมือถือ (และจะทำอะไรบนเว็บ)
- วิธีสร้างไอคอนแอปทุกขนาดจาก SVG ในข้อ 9

ตัวเลือกที่เคยคุยกันไว้คร่าวๆ (เป็นแค่จุดตั้งต้น ไม่ใช่ข้อบังคับ): drift หรือ hive_ce สำหรับเก็บข้อมูล, riverpod สำหรับ state, intl สำหรับวันที่และสกุลเงิน, fl_chart สำหรับกราฟ, flutter_local_notifications สำหรับแจ้งเตือน

### รูปแบบไฟล์สำรอง (ตัดสินแล้ว — ต้องเข้ากันได้กับต้นแบบเว็บ)

```json
{
  "app": "snowflow",
  "version": 1,
  "exportedAt": "2026-10-03T09:00:00.000Z",
  "entries": [
    {"id": "abc123", "type": "expense", "amount": 60, "currency": "THB",
     "category": "food", "date": "2026-10-03", "note": "ข้าวมันไก่", "created": 1790000000000}
  ]
}
```

- นำเข้า: ตรวจว่า `app` เป็น `"snowflow"` (รับ `"money-notebook"` จากต้นแบบเก่าด้วย) ข้ามรายการที่ข้อมูลไม่ครบ หมวด `other_e` / `other_i` ให้แปลงเป็น `other`
- ถามผู้ใช้ทุกครั้งว่า **แทนที่ทั้งหมด** หรือ **รวมข้อมูล** (รวม = ข้ามรายการที่ id ซ้ำ)

## 4. ฟีเจอร์

### 4.1 จดรายการ (เพิ่ม / แก้ไข / ลบ)
- ฟิลด์: ประเภท (รายจ่าย/รายรับ, ค่าเริ่มต้นรายจ่าย), จำนวนเงิน, สกุลเงิน (ค่าเริ่มต้นคือสกุลที่ใช้ล่าสุด ถ้าไม่มีใช้สกุลเริ่มต้น), หมวด (ค่าเริ่มต้นหมวดแรก), วันที่ (ค่าเริ่มต้นวันนี้ เลือกย้อนหลังได้ ห้ามเลือกอนาคต), โน้ต (ไม่บังคับ)
- ตรวจ: จำนวนเงินต้องมากกว่า 0 ถ้าไม่ผ่านแสดงข้อความ "ใส่จำนวนเงินที่มากกว่า 0"
- เปิดฟอร์มแล้วโฟกัสช่องจำนวนเงินทันที แป้นพิมพ์ตัวเลขทศนิยม
- แตะรายการในหน้ารายการเพื่อแก้ไข มีปุ่มลบพร้อมยืนยัน

### 4.2 หน้ารายการ
- การ์ดคงเหลือ (BalanceCard) ของรอบปัจจุบัน ในสกุลเงินเริ่มต้น
- รายการจัดกลุ่มตามวัน ใหม่สุดก่อน หัวกลุ่มแสดง "วันนี้" / "เมื่อวาน" / ชื่อวัน + วันที่ และยอดสุทธิของวันนั้นแยกตามสกุลเงิน
- ว่างเปล่า: "ยังไม่มีรายการ กดจดรายการเพื่อเริ่ม"
- เว็บ: คอลัมน์ขวามีการ์ด "ใช้มากที่สุดเดือนนี้" (4 หมวดแรก) และลิงก์ไปหน้าสรุป

### 4.3 หน้าสรุป
- เลือกสกุลเงิน (แสดงเฉพาะสกุลที่มีรายการจริง) — **ไม่แปลงค่าเงินข้ามสกุล**
- สลับ **รายวัน** (วันในรอบเดือน) / **รายเดือน** (รอบเดือนในปี)
- เลื่อนช่วงก่อนหน้า/ถัดไป
- การ์ดยอดรวม 3 ใบ: รายรับ, รายจ่าย, คงเหลือ ของช่วงที่แสดง
- กราฟแท่งรายจ่าย ซ้อนสีตามหมวด (stacked) มี legend
- แตะแท่ง → เลือกช่วงนั้น แท่งอื่นจางลง แท่งที่เลือกมีกรอบสี `accent` และยอดรวม/อันดับหมวดเปลี่ยนเป็นของช่วงที่เลือก แตะซ้ำหรือกด "ดูทั้งช่วง" เพื่อยกเลิก
- อันดับหมวด "เงินหมดไปกับอะไร": เรียงมากไปน้อย พร้อม % และแถบความยาวตามสัดส่วน

### 4.4 รอบเดือน (สำคัญ — เขียน test)
- ผู้ใช้ตั้ง `cycleStartDay` ได้ 1–31 ค่าเริ่มต้น 1
- รอบหนึ่งเริ่มวันที่ `cycleStartDay` ของเดือน และจบก่อนวันเริ่มของรอบถัดไป
- ถ้าเดือนนั้นสั้นกว่าวันที่ตั้ง ใช้วันสุดท้ายของเดือนแทน (เช่น ตั้ง 31 → กุมภาพันธ์เริ่มวันที่ 28/29)
- ป้ายชื่อรอบ: ถ้าเริ่มวันที่ 1 แสดงชื่อเดือน เช่น "ตุลาคม 2569" ถ้าไม่ใช่ แสดงช่วง เช่น "25 ก.ย. – 24 ต.ค. 2569"
- **เงินคงเหลือ = รายรับของรอบ − รายจ่ายของรอบ** ไม่สะสมข้ามรอบ
- แถบความคืบหน้าในการ์ดคงเหลือ = รายจ่าย ÷ รายรับ ของรอบ (สูงสุด 100%) ถ้ายังไม่มีรายรับแสดง "ยังไม่มีรายรับเดือนนี้"

- card: `0 2px 10px rgba(15,42,54,0.06)` (มืด `rgba(0,0,0,0.35)`)
- bar (แถบล่างมือถือ): `0 -4px 20px rgba(15,42,54,0.07)`
- add (ปุ่มจดรายการ): `0 12px 22px rgba(31,95,117,0.35)` + วงรอบสี tint 6px

### หลักการ
- **ไม่ใช้เส้นคั่น** ระหว่างแถวหรือส่วนต่างๆ แยกด้วยระยะห่างและเงานุ่ม
- จุดกดสูงอย่างน้อย 44px
- สีที่ต้องแยกกัน (รายรับ/รายจ่าย) ต่างกันทั้งสีและความสว่าง
- ไอคอนลายเส้น 1.8px ขนาด 20–24px ปุ่มจดรายการใช้ไอคอน **ดินสอ** ไม่ใช่เครื่องหมาย +

## 7. Layout

breakpoint: **กว้าง ≥ 900px = เลย์เอาต์เว็บ/แท็บเล็ต**, น้อยกว่านั้น = เลย์เอาต์มือถือ

### มือถือ
- หัวจอ: โลโก้ + "SnowFlow" (หน้ารายการ) หรือชื่อหน้า, ปุ่มฟันเฟือง (ตั้งค่า) มุมขวาบน
- แถบล่าง 3 ช่อง: **รายการ | ปุ่มจดรายการ (ตรงกลาง) | สรุป**
  - ปุ่มจดรายการ: สี่เหลี่ยม 58×58 มุม 20 สี brand ไอคอนดินสอสี on-brand ยกลอยขึ้นเหนือแถบ ~28px มีวงรอบสี tint 6px และเงา add ป้าย "จดรายการ" ตัวหนาสี brand ใต้ปุ่ม
- ตั้งค่า: เปิดเป็นหน้าซ้อน มีปุ่มกลับมุมซ้ายบน ไม่แสดงแถบล่าง
- ฟอร์มจดรายการ: แผ่นเลื่อนขึ้นจากด้านล่าง มุมบน 26 มีที่จับ วันที่กับโน้ต **คนละบรรทัด**

### เว็บ (≥ 900px)
- sidebar ซ้ายติดจอ พื้น surface เงาขวานุ่มๆ ไม่มีเส้นขอบ
  - ย่อ (ค่าเริ่มต้น) กว้าง 88px แสดงแค่ไอคอน / ขยาย กว้าง 248px แสดงชื่อ จำสถานะไว้
  - ลำดับบนลงล่าง: โลโก้ + "SnowFlow", ปุ่มจดรายการ (สูง 52 มุม 16), เมนู รายการ/สรุป/ตั้งค่า (สูง 48 เมนูที่เลือกพื้น tint ตัวอักษร brand), ช่องว่าง, **ปุ่มย่อ/ขยาย (ไม่มีพื้นหลัง)**, ข้อความกุญแจ "ข้อมูลเก็บในอุปกรณ์นี้เท่านั้น" (บรรทัดสุดท้าย)
  - ตอนย่อ ชี้เมาส์ที่ไอคอนแสดงชื่อ (tooltip)
- หน้ารายการ: สองคอลัมน์ — ซ้ายรายการ, ขวา (กว้าง ≥ 360) การ์ดคงเหลือ + การ์ดหมวดที่ใช้มากที่สุด
- หน้าสรุป: การ์ดยอดรวมแถวบน, กราฟซ้าย, อันดับหมวดขวา
- ฟอร์มจดรายการ: กล่องกลางจอ กว้างไม่เกิน 560 วันที่กับโน้ตอยู่บรรทัดเดียวกัน ปุ่ม ยกเลิก/บันทึก ชิดขวา

## 8. คอมโพเนนต์หลัก

- **BalanceCard:** พื้น glacier มุม 26 padding 22 วงกลมโปร่ง (hero-tile) ขนาด 200 ล้นมุมขวาบน / แถวบน: "คงเหลือเดือนนี้" + ชิปเดือน / ตัวเลขคงเหลือ 44 bold / แถบความคืบหน้าสูง 8 (เติมสี hero-ink) + ข้อความ "ใช้ไปแล้ว X% ของรายรับเดือนนี้" / ไทล์ รายรับ-รายจ่าย 2 ใบ พื้น hero-tile มุม 16 มีวงกลม surface ใส่ลูกศรสี income/expense — **ถ้าการ์ดแคบให้ไทล์เรียงบนลงล่าง และห้ามตัดตัวเลขเป็น "..."**
- **EntryRow:** ไทล์หมวด 42 | ชื่อหมวด (600) + โน้ต (caption) | ยอดเงิน (รายจ่ายสี ink นำหน้า "−", รายรับสี income นำหน้า "+") ทั้งแถวกดได้ ไม่มีเส้นคั่น
- **TextField:** พื้น surface-2 ไม่มีกรอบ มุม 14 สูง 48 มี label เสมอ / ช่องจำนวนเงิน: สูง 68 กรอบ brand 2px ตัวเลข 34–36 bold ต้องหดได้ไม่ล้นจอ
- **Dropdown / Date / Time picker:** ใช้ไอคอนของแอปเอง (ลูกศรลง, ปฏิทิน, นาฬิกา) สีตามธีม ไม่ใช้ไอคอนระบบที่สีไม่ตามธีม
- **Segmented:** ราง surface-2 มุม 12 ปุ่มสูง 36 ตัวที่เลือกพื้น surface + เงา card + ตัวหนา
- **CategoryPicker (ในฟอร์ม):** ตาราง 4 คอลัมน์ ปุ่มสูง 78 พื้น surface-2 ที่เลือกมีกรอบ brand 2px พื้น tint

## 11. ลำดับการทำงานที่แนะนำ

เป็นข้อเสนอเบื้องต้น ปรับได้หลังวางแผนสถาปัตยกรรมเสร็จ


1. ตั้งโปรเจกต์ Flutter (web/ios/android), ใส่ฟอนต์ Prompt, ธีมสว่าง/มืดจาก token ข้อ 6, ระบบแปลภาษา th/en
2. Data layer: model, storage ในเครื่อง, repository + unit test
3. Logic: รอบเดือน, ยอดคงเหลือ, การจัดกลุ่มสรุป + unit test
4. หน้ารายการ + ฟอร์มจดรายการ (เพิ่ม/แก้/ลบ) — เลย์เอาต์มือถือก่อน
5. หน้าสรุป + กราฟ
6. หน้าตั้งค่า + ส่งออก/นำเข้า
7. เลย์เอาต์เว็บ (sidebar ย่อ/ขยาย, สองคอลัมน์, ฟอร์มกลางจอ)
8. แจ้งเตือนรายวันบนมือถือ, ไอคอนแอป, ข้อมูลตัวอย่างสำหรับทดสอบ
9. ทดสอบบนเว็บ, iOS simulator, Android emulator ทั้งสองธีมและสองภาษา

## 12. เกณฑ์ว่าเสร็จ (MVP)

- จด แก้ ลบ รายการได้ทั้งรายรับและรายจ่าย หลายสกุลเงิน
- การ์ดคงเหลือและหน้าสรุปคำนวณตามรอบเดือนที่ตั้งถูกต้อง (มี test ครอบคลุมกรณีวันที่ 29–31)
- ปิดแอปแล้วเปิดใหม่ ข้อมูลยังอยู่ ใช้งานได้แบบออฟไลน์
- ส่งออกแล้วนำเข้าอีกเครื่อง/อีกแพลตฟอร์มได้ข้อมูลครบ
- ธีมสว่าง/มืด/ตามระบบ และภาษาไทย/อังกฤษ เปลี่ยนได้ทันที
- ไม่มีข้อความหรือตัวเลขล้นจอที่ความกว้าง 360px และไม่มีเส้นคั่นนอกจากเส้นฐานกราฟ
